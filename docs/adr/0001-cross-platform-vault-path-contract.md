# Cross-platform vault path contract

Vault-relative paths exposed through the agent-facing interface use `/` on every operating system, while inputs accept both `/` and `\\`; absolute filesystem paths remain native and internal. Path arguments remain vault-relative, so Unix absolute paths, Windows drive-letter paths, and UNC paths are not part of the tool contract, although a configured Windows UNC directory is a valid internal vault root. Note identity and Markdown extension matching follow host filesystem case rules, search lines exclude CRLF line-ending characters, platform-native Obsidian configuration locations are preferred, and optional external commands must fall back without changing core behavior. The compatibility build guarantees ordinary Node-supported paths and Unicode content, but does not add bespoke semantics for permissions, locks, junctions, device names, or system path-length policy. This keeps tool results stable for agents while preserving the host platform's filesystem behavior behind the interface.
